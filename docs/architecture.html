01

为什么需要它？—— LLM 记忆四难

模型本身没有记忆，而"记忆方案"普遍在容量、成本、进化、迁移之间顾此失彼。

🔒

容量受限

内置记忆只有数千字符，跑几个月就满。删旧信息 = 丢经验；不删 = 记不进去。

💰

上下文即成本

把记忆全塞进 prompt 最贵：100 条记忆 ≈ 5 万 Token/会话，月成本数十美元起步。

🧬

只存不进化

传统方案是"聊天记录仓库"——只增不减、重复冗余、过时信息淹没有效信息，知识不会生长。

📦

难以迁移

记忆锁死在某个 Agent / 某台机器里，换工具、换人、换环境就全部归零。

02

越往顶层越精炼（价值密度越高）；底层海量原始数据，顶层固化方法论。L4 外部知识随时接入。

03

核心机制：三条设计底线（v2）

v2 架构的三大支柱：类型分层冲突处理、双信号生命周期、性能红线（ADR-0001/0003/0005）。

⚖️
BOTTOM LINE 01

类型分层 · 冲突立场

条目分三类：事实类（可附外部依据，由你拍板）、认知类（保留沿革链 superseded_by，不静默覆盖）、偏好类（永不纠正）。系统给结论，你查依据——不做应声虫。

fact/belief/preference冲突卡沿革可追溯
💡 你检索时会撞见自己的认知演化历史，而不是自我重复的回声室
🌡️
BOTTOM LINE 02

双信号生命周期

条目的冷热由更新频率 + 读取频率共同决定：长期未更新且未被读 → 衰减归档；被频繁读取 → confidence 回升。记忆库的冷热由你的实际使用塑造。

last_accessed衰减不误杀使用即复活
💡 老而常用的核心知识永不误杀，陈年垃圾自然沉底
⚡
BOTTOM LINE 03

性能红线：LLM 不进热路径

add/search/get 零 LLM、零网络（仅本地正则/SQL）；所有智能机制（补扫/冲突/衰减/草稿）挂每周 consolidate 批处理。实测：daemon 写入 ~100ms（v1 的 1.3s），检索 2-3ms。

热路径零 LLMdaemon 常驻机制再多也不慢
💡 慢的不是双保险，是把 LLM 放错路径（ADR-0005）

06

安全设计（Key 与敏感记忆）

🔑 防线① 写前拦截

凭证类（sk- / AKIA / ghp_ / 私钥 / Bearer）→ 拒绝写入；敏感类（内网 IP / 手机号 / 邮箱 / Cookie）→ 自动标 secret（摘要隐藏、get 需 --force、不发给 LLM、不进 PRELOAD）。

🔒 防线② 周扫补检

consolidate --mode llm 对近 7 天条目规则补扫，漏网的自动标 secret 并提示——把漏网之鱼变成事后发现。

🧹 防线③ 提交闸门

git pre-commit 全量扫描（含新增文件），Block 级命中拒绝提交；--no-verify 需人工显式绕过。LLM 数据边界：secret 条目绝不外发。

📦 分发安全

架构包自动剥离个人记忆：不含 .env / 索引 / 任何真实条目，只带示例骨架；三层规则共用 security_rules.py 保证一致。

07

使用体验：三个瞬间

不需要学命令、不需要记流程 —— 记忆在三个自然瞬间悄悄发生。

🛟

踩坑的瞬间

全自动

agent 会话中发现踩坑/被纠正/新知识 → 自主 capture 写入，无需确认；写前安全拦截自动标记敏感内容。

capture --body "Excel 打开大断面 CSV 要用 utf-8-sig" # 类型/分类自动推断
🔍

需要的瞬间

自动

任务涉及老经验 → 毫秒级检索出相关记忆；要答案时 --synthesize 给出带 [来源:path] 的综合回答，可展开验证。

search "水位基面换算怎么做" --synthesize # 结论带来源
📅

每周的瞬间

喊一声

consolidate 自动完成：双信号衰减、去重、敏感补扫、语义冲突→冲突卡（你拍板）、模式→SKILL 草稿。

consolidate --mode llm # 一次跑完五件事
