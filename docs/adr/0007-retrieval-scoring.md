# ADR-0007: 检索打分 — 词覆盖率优先，多因子只作放大器

- 日期：2026-10-26
- 状态：已接受
- 相关：ADR-0005（LLM 永不进热路径）、ADR-0006（溯源标签与更正流）

## 背景

旧实现（`cmd_search`）只做**二值命中**：

1. `entries_fts MATCH <整串查询>` —— FTS5 把空格分隔的多个词当 `AND`，且用 `trigram` 分词；
2. LIKE `%<整串>%` 兜底 —— 只能匹配**连续子串**；
3. 打分 = `FTS命中+10 / LIKE+4 / 标题含+5 / 摘要含+2 / hits×0.1`。

三个后果（2026-10-26 实测，20 个真实查询）：

- **多词不连续即零结果**：`同步 频率` → 0 条（而 `同步` 单词 → 20 条）；
- **2 字中文词零结果**：trigram 索引对不足 3 字的词完全失效（`排频`）；
- **自然语言整句零结果**：`怎么做整页图片式PPT`。

**零结果率 10/20**。同时排序里没有任何时间/重要度/使用频次因子，`hits` 只在 `get` 时累加（全库累计命中 = 2），

等于用一个恒为 0 的信号在排序。

## 决策

检索改为「**词覆盖率优先 + 多因子只作放大器**」，全程零 LLM、零网络、零新依赖（只用 SQLite + numpy 之外的纯标准库）：

1. **切词**：按空白/中英标点切分；连续中文不硬切，交给第 3 步。
2. **候选并集**：每个词的三字组做 `OR`（FTS5 `bm25` 排序）+ 短词/2 字词走 `LIKE` 兜底。
   长句因此天然获得"任一片段命中即候选"的模糊能力。
3. **长句部分覆盖**：词长 ≥6 时，用 **2 字组 + 稀有度权重** `log(1+N/(1+df))` 计算覆盖，
   并**剔除库中不存在的片段**（跨词碎片如"库多久""步到远"若保留，会以 df=0 拿到最高权重、把分母拉爆）。
4. **加权**：`final = 覆盖率 × (0.75 + 0.25×新鲜 + 0.10×重要度 + 0.05×访问)`。
   相关性以外的三因子**只能放大 0.75–1.15，不能独立加分**——参考 Hy-Memory 的四因子思路，
   但**不接受它的加法形式**：加法下"最差查询里最不差的那条"也会因新鲜度顶到 70 分。
5. **弱命中告警**：最高分 <50 时明确提示"词法未找到可确认的记忆"，建议换词或 `--synthesize`。
   词法检索无法证明"库中无此记忆"，不假装命中、也不静默给垃圾。
6. **访问反馈闭环**：检索命中即 `hits+1`；`rebuild_index` 按 uid 备份并回填 `hits/last_accessed`。
7. **单一真相源**：抽出 `search_items()`，CLI 与 `daemon._daemon_search` 共用（此前 daemon 复制了一份旧逻辑）。

## 备选方案（评估后否决）

| 方案 | 否决理由 |
|---|---|
| **本地语义向量混合**（fastembed + `bge-small-zh-v1.5`，616 条暴力余弦，0.55/0.45 混合） | 实测**无增益**：召回@5 0.93→0.92、top1 14/16→13/16；4/4 改述查询 top1 条目完全相同（仅分数虚高）；单次检索 0.3s→3.3s，且每台设备多 91MB 模型 + 一个 pip 依赖。根因：本库词法已做 2 字组稀有度加权，改述能力被吃掉大半；bge-small 对 600–1200 字长条目区分度不足。 |
| LLM 做 query 改写 / 同义词扩展 | 违反 ADR-0005（LLM 不进热路径），且检索是最热路径。 |
| 上向量数据库（Chroma/Qdrant/FAISS）或图库 | 数百条规模的暴力余弦都在毫秒级，属基础设施过重。 |
| 保留"`MATCH` 整串 + 无命中时再放宽"的两段式 | 放宽后排序仍无区分度；且两段逻辑会让"为什么这条没查到"难以解释。 |

## 后果

- 正面：零结果 **8/16 → 0/16**、平均召回@5 **0.26 → 0.92**、top1 精确率 **5/16 → 14/16**；
  单次检索 0.3s 与改前持平；自然语言提问可直接用，不必先想"库里用了什么词"。
- 代价：一次查询会多做 N 次 `LIKE`/`COUNT`（N = 查询词数 + 长句片段数），在 600 条量级仍是毫秒级；
  条目涨到万级时需要重新评估（届时优先考虑 FTS5 的 `unicode61` + 中文分词，而不是向量库）。
- 已知上限：**语义近似改述仍可能排序不佳**（例：正文含"远程仓库"的无关条目会被"记忆库多久同步到远程仓库一次"排到前面）。
  这是词法检索的固有边界，靠第 5 条的弱命中告警把不确定性暴露给调用方，而不是用重基础设施掩盖。
- 回归保障：`tests/test_search_rank.py` 11 项（多词不连续 / 2 字中文 / 整句 / 覆盖率排序 / hits 累计 /
  重建保留 hits / `applies_to` / 弱命中判定），全量 78 项通过。
