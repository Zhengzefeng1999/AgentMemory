# ADR-0002: 三层安全网

- 日期：2026-08-11
- 状态：已接受

## 背景

2026-08-10 事故：D:\AgentMemory 本地 git 历史含真实姓名、单位、内网 IP、FastGPT、微信 Cookie，险些推送到公开仓库（Zhengzefeng1999/AgentBank 为 PUBLIC）。纯正则规则无法拦截"微信 Cookie"这类非标准格式敏感信息；纯 LLM 扫描无法在写入前阻止落盘。

## 决策

三层防线，各司其职：

1. **写前规则拦截（热路径，零 LLM）**：正则黑名单在写入前执行。
   - **Block 级**（凭证）：`sk-` 长串、AKIA、`ghp_`、bearer token、私钥块、密码赋值 → 拒绝写入。
   - **Mark 级**（敏感）：内网 IP、手机号、身份证、Cookie、敏感路径 → 不拒绝，自动标记 `secret: true`（摘要隐藏、get 需 --force、不发给 LLM）。
2. **consolidate LLM 补扫（冷路径，每周）**：对近 7 天新增条目做敏感内容补扫，命中自动标 secret 并提示。复用现有 call_llm 管道，结果不外发。
3. **pre-commit 全量扫描闸门（提交前）**：git 提交时扫描全部已暂存文件（含新增），任何 Block 级命中拒绝提交；`--no-verify` 需人工显式绕过。

## 备选方案

- 仅规则拦截：漏非标准格式（上次事故即此类）。
- 仅 LLM 扫描：写入前无法阻止落盘。
- 仅 pre-commit：先污染本地历史，清理成本极高（clone/fork 缓存无法根除）。

## 后果

- 三层定位：**拦截（写前）→ 发现（周扫）→ 闸门（提交前）**，任一漏网有下一层兜底。
- 成本：热路径仅正则匹配（µs 级）；周扫复用 consolidate；pre-commit 在提交节奏内。
- 权衡：内网 IP 等 Mark 级内容允许本地记录（水文工作区正常需记录内网数据源），但永远不出现在检索摘要、不发给 LLM、不能无 --force 读取。
